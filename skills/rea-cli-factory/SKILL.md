# REA CLI Factory

交付可重复执行任务的适配器、使用说明和真实结果证据。先围绕少量高频任务工作；不要把“能分析整个应用”作为“能控制整个应用”的保证。

## 确定目标与入口

- 由用户指定的名称、路径或当前明确目标选择应用；多个安装副本不能自动选一个。macOS 可用 `python3 scripts/inventory_app.py --app '/absolute/App.app'`，或 `--name 'App'` 精确查找标准安装目录。脚本只读取包内身份和文件摘要，不启动应用、不读取账号数据。
- 查找已经安装的适配器、官方 API、CLI、脚本与插件接口。优先复用满足任务的稳定入口。有完整源码时正常读源码，不为形式完整而运行 REA。
- 需要从发布包恢复行为时，读取已安装的 `reverse-engineer-anything` Skill，按当前工具 schema 或 CLI `--help` 调用。ASAR/提取的 JS 用应用分析，原生文件按相应 provider 处理。记录 REA 实际版本和调用参数，不能从技能文件的工具列表推定当前工具可用。
- 工具缺失时检查可用 CLI 和已配置环境；安装指引不是已接通的证据。无法执行 REA 就明确标注，普通文件检查的输出不能包装成 REA Evidence。继续做已有证据支持的工作。

## 多应用验证

多应用任务按 [验证协议](references/multi-app-evaluation.md) 选择不同控制入口，使用 `scripts/probe_app.py` 做有限静态路由。候选不代表可调用，原生接口可用时不强制 REA。每个样本用隔离输入和真实产物读回验收，应用适配器默认不随通用工具公开。

## 将发现变为可调用能力

为每个任务追踪：用户动作 → 候选入口 → 所需状态/参数 → 真实结果 → 可独立检查的成功条件。保留来源文件、摘要、REA Evidence ID（实际返回时）、覆盖范围及剩余未知。

区分 `candidate`（静态发现）、`callable`（真实调用被接受）、`verified`（结果读回成功）、`blocked`（有具体阻塞）与 `unsupported`（本适配器不支持）。不要根据字符串、IPC 名称、网络端点或函数签名直接生成“已支持”命令。

对于本地 REA JavaScript JSON，可用 `scripts/summarize_rea.py --input evidence.json --query <feature>` 读取小摘要，保留源位置与覆盖范围；摘要不替代原始 Evidence，不验证其签名/摘要，也不自动证明运行时可达。输出用于本地开发，不作为自动脱敏发布材料。

REA 的 partial/超时结果应保留已完成证据和缺口。先查看局部记录或缩小到相关模块；除非新增问题确实依赖缺失部分，不强制全量重跑。精选文件的分析不能称作完整应用分析。

Electron 候选需验证对应进程/页面、既有 preload/contextBridge 和实际可达性。被动观察不等于动作执行。使用另一个执行器时写明边界，绑定实际应用及目标身份，限定到任务所需操作。需要 GUI、登录或本地调试会话就如实标注，不能称为无界面自动化。

## 制作适配器

把首次开发与日常运行分开：已有已验证适配器时直接执行任务命令，仅在不兼容或实际故障时重新分析。高频任务提供一次调用的完整流程，复用同一会话，保留版本检查、目标核对和结果验证；减少 Agent 往返以及重复打开页面。记录搜索/准备、动作等待、验证保存、清理耗时，区分 CLI 耗时与用户等待的整体时间。结果已验证后及时交付，不把无关开发与整理放到普通任务路径中。

借鉴 CLI-Anything 的真实软件后端、结构化输出和端到端验证方法，语言与命令结构按目标选择；这不意味着自动符合其 Click/REPL/发布标准。方法与产物契约见 [references/adapter-contract.md](references/adapter-contract.md)。

- 操作核心与 CLI 参数层分开；按任务提供明确子命令，加入 `--help`、机器可解析输出、稳定错误码、超时和只读状态检查。允许 JSON 成为默认输出，说明清楚即可。
- 对外命令调用真实应用/真实后端。不要用 mock、另一个库的近似结果或内部状态文件写入冒充完成。
- 记录适配版本和关键 artifact hash。依赖内部接口时，在调用前检测不兼容版本/摘要；变化后重新验证受影响命令。比较值应来自批准的测试样本，不能启动时把当前任意版本自动当作已验证版本。
- 重试前分辨失败是否已产生副作用。操作尚未确认完成时，返回可定位状态；避免重复创建、重复发送或重复扣费。测试只清理本次明确创建的对象。
- 凭据保持在已有应用会话或适当的凭据机制内。日志、JSON、证据包不收集 cookie、token、密码、原始认证响应。用户请求决定可执行动作范围，Skill 本身不扩展授权。
- 用户需要 MCP 时，将同一操作核心通过匹配当前 SDK/协议的 server 暴露为窄工具；验证工具发现、参数错误、调用结果。仅写出 server 文件不算完成安装或接入。

## 验证与交付

先定义验收任务，再调用实际安装入口执行。对修改操作检查读回状态；对导出检查最终文件内容；对网页结果检查已完成的结果状态，登录页/空壳/排队响应不能算成功。

覆盖相关故障：应用未启动、目标不匹配、错误参数、连接超时、版本变化，以及有副作用操作的重复执行。使用 mock 仅验证错误处理，不能替代真实后端验收。验证次数与影响相称，不堆砌机械测试。

交付最少包括：操作入口及依赖、适配版本、命令示例、已验证/未验证能力、结果证据、恢复或启动方式。开发文件存在、安装成功、Agent 已发现、业务任务成功四种状态分别报告。样本成功后仅提炼已证实的通用规律，应用专用逻辑留在适配器项目中。
