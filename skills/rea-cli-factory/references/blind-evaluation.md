# 盲测与人工介入记录

目标是衡量通用工具在未见应用上的能力，而不是为成功展示临时补齐应用专用映射。首次失败也是应保留的结果。

## 首次运行

1. 记录应用/版本、窄任务、工具 commit 或文件摘要，以及已经知道的应用信息。只查看安装元数据、包内文件名，不查看业务实现。是否满足“没有现成 CLI”的资格也要记录搜索范围；metadata 没有 bin 不足以证明不存在 CLI。
2. 在新私有目录中运行下面的命令。REA CLI 必须是已经安装、明确指定的 JavaScript 入口。此工具不安装 REA，也不运行目标应用。
3. 保存首次汇总后再读源码、修改生成器或手写适配。每次介入记录触发原因、查看范围、动作、是否改变结果。改进后的重跑称为复测；不要覆盖或重命名首次失败为成功。

```sh
node skills/rea-cli-factory/scripts/analyze_electron.mjs \
  --asar /private/Selected.app/Contents/Resources/app.asar \
  --rea-cli /installed/rea-agents/scripts/rea.mjs \
  --out /private/new-trial
```

输出包括 `preparation.json`、`run-input.json`、精选 `sources/`、完整 `rea-evidence.json`、逐文件 `contracts/` 与 `analysis-summary.json`。全部包含应用信息，保持私有。`run-input.json` 记录工具与分析器入口摘要，仍需操作者额外记录先验知识和人工介入；工具不能自行证明人没有读过源码。

## 选择与失败边界

准备器仅选择根 package.json、文件名为 preload 或位于 preload 目录中的 `.js/.cjs/.mjs`，排除 node_modules 与 source map。记录原包摘要、文件摘要、字节位置和相对路径；这证明选中文件来自该次读取的包，不证明运行时使用该文件。目录名规则会漏掉其他布局，缺失时停止并记录人工选取，不能扩大为“该应用没有接口”。

限制：包 4 GiB、头部 16 MiB、100,000 条目、深度 64；选中最多 64 文件、单个 2 MiB、合计 16 MiB。选中的链接或 unpacked 文件拒绝读取；无关链接/unpacked 条目跳过。重复键、路径冲突、越界和重叠范围、截断或读取期间变化均失败。只创建新输出目录。

REA 进程总时限 180 秒，单文件分析参数为 60 秒；stdout 最多 64 MiB，stderr 最多 1 MiB。超限/超时保存可用的部分输出但不当作完整 Evidence。停止原进程组并关闭读取管道，避免继承管道的后代拖住返回；此机制不是任意分析器的沙箱，不保证控制已脱离进程组的后代。应使用可信已安装分析器。一次分析失败后只针对原因修复，不盲目重跑。

- 退出码 0、`candidate`：有候选且所有选中文件完成提取。仍需选择方法、生成 CLI 和真实验证。
- 退出码 3、`blocked`：没有候选；`incomplete`：某些文件存在提取错误，即使其他文件有候选也不能当作整体成功。
- 退出码 2：准备或分析阶段失败，若已创建目录则保留阶段失败记录。

`unsupported` 会保留源码位置和具体原因。[模块解析器](module-resolution.md) 可以处理限定的 CommonJS 包装器、工厂和静态通道表；未解析的 Electron 别名、动态业务通道、复杂对象组装、无暴露 API 等仍有缺口。不能通过执行所分析源码、猜测通道或降低证据要求，把这些条目变成候选。ESM、条件暴露或只提供任意通道转发器的应用不属于已验证子集。

## 后续与计时

有候选时复用 [生成流程](bridge-generation.md)；仍须人工确认任务含义、业务参数、入口与页面归属、隔离启动及独立成功条件。没有候选时可以完成本次盲测并报告边界，不声称已经交付可用 CLI。应用专用适配器和原始证据不进入公开仓库。

分别报告首次盲测、工具改进后复测、合成测试和真实应用验证。计时明确包含哪些阶段；已有输入重跑耗时不等于用户等待时间。减少命令编排与诊断往返，不等于消除了业务分析。
