# 模块与工厂解析边界

`discover_modules.mjs` 提供 `discoverModules(sources, entryName, evidence)`。sources 是相对文件名到源码文本的对象；输入来自私有准备目录和对应 REA 证据。它只解释受限 AST，不 import、require、eval 或运行所分析应用的代码。

## 可以恢复的结构

- 字面量相对 CommonJS require、常量 exports / module.exports，以及未修改的字面量通道对象。
- ESM Electron 命名/命名空间导入、限定的相对 named/default 导入与显式再导出；不支持 export star。
- 返回对象的工厂函数、ObjectMethod、嵌套对象，以及通过参数传入的已知 IPC 包装器。
- 单个 invoke/send 调用链；原包装器中的纯返回字段投影、有限分支与简单 Error 构造保留在原方法中。
- 属性级别的修改跟踪：未知条件修改某个属性时，不能使用该属性；未受影响且来源可证实的相邻属性可继续分析。

运行时仍调用 `window` 上的原始方法。不用恢复出的通道绕过应用包装器直接发 IPC，不改写应用的返回值或错误处理。参数名/数量不等于业务 schema。

## 证据与拒绝条件

每个依赖模块必须存在于提供的源码映射中，摘要对应 REA 观察；IPC 叶节点的文件、起止位置和操作类型必须匹配。REA 对参数通道可能只记录 dynamic；工具另做有限的跨文件静态推导，此时分别记录 `channelResolution: scoped-static-inference` 与 `reaResolution: dynamic`，不得声称 REA 已解析出该值。

候选保留方法位置、IPC 位置、多文件摘要以及 coverage；这些信息不证明运行时可达或业务成功。生成器把多文件来源带入私有配置。安装包固定基线和运行时身份核对继续生效。

相对模块缺失/循环/越界/歧义、摘要变化、错误 IPC 位置、动态通道、多个操作、未知副作用、危险响应构造器、参数遮蔽、接口替换或逃逸都拒绝。对象 spread、无法求值的初始化器与复杂条件保持不支持。惰性 getter 自身保持 unsupported；未读取的 getter 不阻断相邻方法，实际 getter 访问或突变会保守失效。

仅支持固定 `process.contextIsolated` 分支及有限 try 包装内的暴露，并可合并另一分支向 window 暴露同一个不可变对象。不同对象、未知条件、覆盖与别名修改仍拒绝。availability 记录条件和原入口存在性检查，不证明该条件在运行时成立。已经被修改的属性、函数或通道不能通过工厂缓存旧值、别名、闭包或条件 exports 绕过检查。

模块分析输入上限为 32 文件、每个 2 MiB、总计 8 MiB，最多 200,000 分析步骤、递归深度 64，并限制函数分析数量。它比包准备器的选择上限更小；达到上限时报告具体错误，不能当作接口不存在。模块依赖只从已准备的输入读取，不自动扩大到整包或 node_modules。

## 与现有生成器协作

流水线以模块解析器的安全判断为准，旧单文件结果只用于冲突否决，不能复活已拒绝的接口；参数、数量、传输方式或通道存在冲突时，不生成该方法。仍由操作者显式选择少量任务方法，再交给 `generate_bridge_cli.mjs`。

未知应用先冻结工具摘要、运行首次分析，再查看实现。应用隔离启动、任务语义和独立验收仍需人工决定。受限 ESM/条件暴露和 [gateway 业务绑定](gateway-binding.md) 已加入；复杂代理、任意总线及任意 GUI 仍不在保证范围内。
