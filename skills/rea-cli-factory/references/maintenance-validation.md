# 重启读回与升级失效验证

适用已完成首次真实调用的适配器。复用已有证据，不为维护检查重新分析整个应用。固定基线、重启结果、升级拦截和新版本兼容是四种不同结论。

## 1. 固定已验证的基线

使用 `inventory_app.py` 记录已选 macOS 应用的包身份、Info.plist、主程序及可选 ASAR 摘要。将其保存在私有适配器中，关联真实成功收据。清单本身不是业务验证；首次采集不能自动把任意当前版本晋升为已支持。

`check_compatibility.py --app /Applications/Selected.app --baseline /private/baseline.json` 只读比较固定应用路径、完整身份字段、关键文件集合和各项摘要/大小。它不启动应用、不写基线，不提供自动接受升级的选项。

| 结果 | 退出码 | 调用方应做什么 |
|---|---:|---|
| `ok:true, status:compatible` | 0 | 继续绑定运行时身份，执行已验证的窄任务 |
| `APP_CHANGED` | 3 | 停止启动/业务动作，报告差异与重新验证要求 |
| `INVALID_BASELINE` | 2 | 停止；恢复可靠的固定基线，不能用当前安装覆盖它 |
| `MISSING_ARTIFACT` 等读取错误 | 2 | 停止；保留具体错误，不当作兼容 |

在启动、创建输出和业务写入之前执行门禁；应用启动后、业务动作前再核对实际进程、页面/会话、版本和数据目录，必要时重查摘要。检查只是某时点关键文件匹配，不是整个应用签名验证，也不能锁住随后发生的更新。

Python 调用返回字典，调用者必须执行门禁：

```python
result = check(app_path, fixed_baseline)
if not result["ok"]:
    return result  # Do not launch or act.
return perform_verified_task()
```

## 2. 重启后只读回，不重放原写入

1. 首次写入结束时保存对象路径或稳定 ID、内容/结构断言、摘要、profile 身份、进程身份与退出结果。
2. 确认上次自有实例已退出、调试端点不再可用。PID 已被复用或归属不明时停止，不杀掉该进程。
3. 以同一私有测试 profile 启动新实例，绑定新进程与正确应用页面；不得重建测试对象或重新导入原输入。
4. 通过应用真实接口读取持久化对象，核对正文/结构、数量、稳定 ID 与原收据；独立文件读回作为补充，不能代替应用读回。
5. 写入新的验证收据，关联原收据摘要，保留原证据。注明新旧进程、同一 profile、没有重复写入、结果检查及清理状态。
6. 仅退出本次启动的实例；保留用户原会话。独立 profile 不等于 OS 沙箱，启动仍可能更新应用元数据。

收据路径不能授权访问任意数据：验证 profile 归属、路径边界与符号链接。为同一 profile 的并发动作设置独占保护；失败锁不能盲目清除。若输出已经验证，先交付，再报告清理结果；清理失败不能抹去真实产物，但必须单独说明。

至少做一次负例：在自有测试对象中引入内容或结构不一致，验证明确失败、不发出成功交付事件、不产生误导性产物；随后恢复原测试内容并再次读回。不得对用户原始资料做破坏性故障注入。

## 3. 升级失效与恢复

优先用合成安装包或隔离副本演练，不为了测试直接升级用户正在使用的应用：

- 改版本号；保持版本号不变而改变内部代码；主程序变化。
- 删除必需文件、增加/移除可选关键 artifact、移动应用路径。
- 基线缺失、格式无效、重复键或摘要非法。
- 断言调用方没有执行启动/业务动作，未写输出、未覆盖基线；只看错误字符串不够。
- 恢复原安装内容后，检查重新匹配；这只证明回到旧版可用，不证明新版已兼容。

适配器集成检查可对未改动的适配器副本注入历史基线不匹配，并监测启动尝试。设置一个匹配基线的 canary，确认监测器确实能探测启动。清楚标注这是故障注入，不是真实升级。

真正换到新版本后，先盘点差异，只对受影响接口补充 REA/代码检查。用新的隔离 profile 完成首次操作、退出重启读回和必要失败验证，才能显式更新固定基线；保留旧基线及适配版本。不能用“忽略 hash”或自动学习当前版本来恢复服务。

## 4. 报告边界

分别报告：首次业务验证、重启持久化验证、模拟升级拦截、真实新版兼容，以及文件就绪与应用清理。计时从 CLI 启动还是从用户请求开始，必须注明。应用专用实现、固定基线、提取源码、profile 和原始收据保持私有；公开部分只包含通用工具、合成测试与经审查的试验摘要。
