# 跨文件工厂解析：Tutti 读回通过，Folo 盲测保留失败

本轮针对上一轮 Tutti 的已知失败开发通用解析能力，再冻结工具文件摘要测试未见应用。Tutti 是开发复测，Folo 才是新盲测；两者不合并计算泛化成功率。

## Tutti：生成的窄 CLI 已真实可用

在 Tutti 0.2.26 的主 preload 入口得到 **54 个候选、11 个不支持项**，可达依赖为两个模块。通用解析恢复了返回对象的工厂方法、跨文件包装器和静态通道表。选中一个读取本地 UTF-8 文本的方法，生成私有 CLI；桥接映射手写数量为 **0**。

真实启动使用独立的应用 profile 和服务状态目录。通过生成的 CLI 读取自制文本，再改变该文本并重新读取；两次返回的内容、文件名和路径都与独立输入一致。文件不存在及参数数量错误均被拒绝。原包装器的响应处理得到保留，调用结果仍为 returned / verified:false；独立验证器比较真实结果后才产生任务 verified 收据。

最终两次读取分别约 **355 ms、202 ms**，仅指已启动会话中的调用，不包括启动、解析、开发或 Agent 往返。冻结版本重新解析出的已选方法描述与实际验收版本一致。退出时核对清理了七个本次启动的应用/服务进程，调试端口已关闭。

只验证了这一个读取任务，没有验证其余 53 个候选、应用写入或持久化能力。人工仍负责：选定窄任务、检查隔离启动/清理方式、定义独立成功条件。应用专用启动器、CLI、测试文件和原始收据均不公开。

## 新应用盲测：Folo 1.6.1

在查看实现前冻结六个通用工具文件的 SHA-256，只知道安装名称、版本和 ASAR 存在；随后运行一次通用命令。首次结果为 **0 个候选、incomplete / SOURCE_PARSE_FAILED**，总耗时 **4,699 ms**（输入准备 111 ms、REA 4,569 ms、发现 12 ms）。REA 覆盖为 partial；没有启动应用或登录账号。

首次结果保存后才查看精选 preload，确认它使用 ESM、条件暴露和通用 IPC 转发方法，业务通道由调用者传入。当前 CommonJS 解析器不能直接处理这些结构；即便仅修复 ESM 语法支持，也不能凭任意通道入口猜出窄业务命令。本轮没有为 Folo 手填通道或覆盖失败结果，没有生成它的可用 CLI。

Folo 的此次人工介入是选定任务范围，以及首次结果后解释缺口；源码选择、REA 与发现命令均由流水线完成。未进行完整应用 CLI 可用性排查，包元数据没有 bin 不足以证明不存在已有入口。

## 通用改进

- 有界、静态的跨文件 CommonJS 与工厂解析，保留多文件来源、方法位置和 IPC 位置。
- 分别标注 REA 观察到的 dynamic 通道与工具静态推导结果。
- 逐属性处理修改，拒绝别名/闭包逃逸、条件导出覆盖、旧值缓存、隐藏副作用和多操作包装器。
- 允许绑定带固定 query 的本地页面 URL，仍逐字核对完整目标。
- 流水线合并两种解析器的一致结果，冲突描述不生成。

验证包含 44 项 Python 测试与 57 项 Node 测试，共 **101 项**；模块专项 25 项，独立审查另外检查了 27 种对抗变体。合成测试、Tutti 真实读回和 Folo 首次失败分别保留，不将静态候选数量当作真实支持数量。

下一缺口是 ESM/条件暴露及“渲染端业务调用 → 通用 IPC 总线”的证据绑定。继续开发时应保留 Folo 作为已见失败样本，再另外选择未见应用评估泛化。
