# ESM、条件暴露与业务通道绑定试验

本轮增加了通用解析能力，**仍未实现 Folo 的无人介入自动适配**。Folo 两个窄命令已有真实调用证据；最终加固后的自动提取保守阻断。新样本 Typeless 首次盲测也保留失败，未将复测或人工选择写成自动成功。

## 通用改进

- 支持限定 ESM 导入/导出和 `process.contextIsolated` 条件暴露；独立处理未读取的 getter。
- 原始 IPC gateway 独立记录，不能直接生成任意通道 CLI。
- 自动从包内 HTML 选择 renderer 入口，分别运行并保存两阶段 REA。
- 对严格限定的纯双层 Proxy 工厂和固定业务调用，恢复具体 channel 与参数数量；运行器固定 channel，调用原 gateway。
- 增加显式自定义本地页面协议支持，继续校验固定应用资源路径、完整 URL、进程和基线。
- 修复旧解析器重新放行已拒绝接口、代理构造器遮蔽/变更、跨文件全局变更和 JSON `__proto__` 参数语义问题。

细节见 [模块边界](../skills/rea-cli-factory/references/module-resolution.md) 与 [通道绑定边界](../skills/rea-cli-factory/references/gateway-binding.md)。仅发布通用代码、合成测试及此摘要。

## Folo 1.6.1：开发验证与最终判定

既有样本的 ESM 语法失败已解决：preload 自动恢复 2 个未绑定 gateway。开发版本的一条命令流程自动选择 renderer、完成真实 REA 并得到 42 个业务候选，耗时 66.18 秒。其中 preload REA 16.05 秒、renderer REA 46.81 秒、绑定 2.55 秒。这是已有样本的开发运行，不是新盲测或用户等待总时长。

从开发阶段自动生成的候选中显式选择两个方法，使用最终通用运行器生成本地适配器并独立验收：

| 任务 | 独立检查 | 实测 |
| --- | --- | --- |
| 读取应用版本 | 与固定包清单比较 | 通过，330 ms |
| 检查自有测试文件存在 | 创建文件后返回 true | 通过，229 ms |
| 检查同一文件已不存在 | 删除本次创建的文件后返回 false | 通过，266 ms |
| 错误参数、未选择的任意 gateway | 调用前拒绝 | 通过 |

这些耗时包含已运行应用上的 CLI 启动、基线/身份检查和调用，不包含首次开发、启动或分析。没有手写桥接映射；但保留并接受开发阶段候选是一次明确的人工决策，不能等同最终提取器通过。最终测试实例的 5 个自有进程已清理，调试端口关闭，固定应用基线未变。

最终审查发现 renderer 包含配置决定的全局属性写入，无法静态排除它替换代理构造器。加固版重放真实、摘要一致的 REA 证据后，结果为 **2 个 gateway、0 个业务候选、blocked**；没有执行混淆代码或忽略这项不确定性来恢复 42。此前真实调用仍证明选中的两个窄任务在所测环境可用，不证明整个代理空间稳定。

仍需人工介入的工作包括：任务语义检查、启动隔离与自定义协议确认、独立结果比较、开发候选的显式接受。首次测试还发现自动更新行为，后续使用外层操作系统网络隔离测试本地只读任务；不把隔离启动模板描述为通用于所有 Electron 应用。源码中也发现应用自身的 CLI 集成，因此 Folo 仅作为既有解析问题样本，不作为新“无 CLI 应用”的资格样本。

## Typeless 2.8.3：冻结版本首次盲测

只检查安装元数据、入口文件名、包声明和官方帮助的有限范围，未发现现成 CLI；这不能证明不存在。它的官方产品定位为语音输入应用，测试任务限定为本地元数据或自有文件读取，未启动录音。[官方介绍](https://www.typeless.com/about)

首次分析前冻结全部通用工具摘要，分析完成后确认未变。工具自行选择 11,314 字节的 ESM preload 并运行真实 REA，**8.00 秒返回 blocked，0 个候选、0 个 gateway**。首次结果前没有人工阅读业务实现、改解析器或补映射。

结果保存后做了一次 preload 定位检查：接口属性名通过混淆字符串表和解码函数计算，超出当前静态子集。未生成适配器、未启动应用；首次失败保持原样。
