# 维护验证：2026-10-23

本轮对上次已验证的 Cherry Studio 1.9.13 实验适配器补充重启读回和升级失效处理。应用专用实现、基线、profile、原始收据仍留在本地。本轮没有安装或升级应用。

## 真实重启读回

两份上轮创建的不同中文 Markdown 均复用原测试 profile；确认原进程退出、原调试端点不可用后，启动新进程，通过应用接口读回原笔记及目录结构，再导出逐字节核对。没有重新导入或创建笔记。两个新实例均已退出，原收据保留并在新收据中关联其摘要。

| 样本 | 文件就绪 | 含退出清理总时长 | 结果 |
|---|---:|---:|---|
| 1 | 4.582 秒 | 6.664 秒 | 应用读回、目录、文件字节匹配 |
| 2 | 2.465 秒 | 3.179 秒 | 应用读回、目录、文件字节匹配 |

时间从 CLI 启动计算，包含兼容性检查和应用启动，不包含开发与 Agent 往返；两次运行不是稳定性能统计。

负例：临时修改一份自有测试笔记后重启，得到 `READBACK_MISMATCH`，没有 `file_ready`、没有导出产物，应用正常退出。恢复原文字节后再次重启成功，证明检查没有只比较上次导出的缓存文件。未修改用户原始资料。

## 升级门禁演练

通用 `check_compatibility.py` 已加入私有 CLI 的启动前和任务动作前检查。固定基线比较包身份、版本、Info.plist、主程序、可选 ASAR、文件大小及固定路径，失败不自动学习当前安装。

两层证据分别验证不同范围：

- 合成 `.app` 测试实际改变版本、同版本 ASAR、主程序及文件集合，检查 APP_CHANGED/读取失败与调用方不执行动作，并验证恢复旧文件后重新匹配。
- 未改动的私有适配器副本分别注入版本不匹配、同版本摘要不匹配、无效基线，均在启动前退出，没有启动尝试、没有输出目录、没有基线改写。匹配基线的 canary 能触发启动监测器，且监测器阻止真实启动，证明监测有效。

这验证的是**升级后拒绝未知版本的处理机制**，不是真实新版本兼容性。匹配只覆盖清单中的关键文件，不覆盖整个应用签名，也不阻止检查后发生更新。
