# 多应用泛化试验：2026-10-22

本轮在三款真实安装的 macOS 应用上，以自建输入执行一个窄任务。应用专用包装器、原始收据和产物留在本地，不随公开仓库分发。下表是手工实机试验摘要；CI 只运行通用工具的离线回归，不能重现这些应用的运行环境。

| 应用与版本 | 控制入口 | 实际任务与读回 | 单次执行耗时 | 状态 |
|---|---|---|---|---|
| LibreOffice 26.2.3.2 | 自带 headless CLI | HTML 转成一页 PDF；独立文本提取核对唯一标记和表格值 | 4.610 秒 | verified |
| Godot 4.7.1 | 自带 headless CLI + 脚本 | 保存场景资源，绕过缓存重新加载、实例化，核对节点名/位置/子节点 | 0.728 秒 | verified |
| CotEditor 7.0.5 | 已声明 Apple Events 脚本接口 | 新建文档，保存中文 UTF-8 文本，精确读回并关闭该已保存文档 | 2.000 秒 | verified |

耗时来自各次执行的计时，包括各包装器的不同预检与验证步骤；不是用户发送消息到收到结果的耗时，不是应用间性能排名，也不是平均值或稳定性保证。

## 得到的可复用规则

1. **先探测入口，再选后端。** 新的 `probe_app.py` 以应用清单为基础，在限定目录检查框架、ASAR、脚本字典和辅助可执行文件，输出 candidate 与路由建议；不执行应用或声称功能可用。
2. **现成 CLI 足够时无需逆向。** 两款应用的原生 CLI 可直接承担任务；脚本字典又提供了第三种控制路径。本轮 `reaExecuted=false`，不能算作 REA 的发现或增量证据。
3. **保存会改变对象身份。** CotEditor 的未命名文档引用在保存改名后失效；泛用 document id 也不适用。最终通过显式求值的文件路径重新绑定自有文档再关闭，已保存测试文档按精确路径清理。该试验仍依赖 GUI/Apple Events 权限，没有验证所有异常下的对象清理。
4. **隔离方式由应用决定。** LibreOffice 使用独立 UserInstallation。Godot 的 custom_user_dir_name 不是绝对路径覆盖；改为唯一 ASCII 名，记录宿主 Application Support 目录边界，仅删除本次新建的空目录。不能把它称为完整文件系统隔离。
5. **成功必须读回业务内容。** PDF 验证内容标记、场景验证重新加载后的结构、文本验证字节/编码内容，而非只看进程退出码或文件存在。

## 失败检查与未覆盖范围

LibreOffice 验证了输出已存在、输入缺失与内容不匹配：拒绝覆盖，失败产物不交付。Godot 验证了重复输出目录拒绝，并纠正用户数据目录假设。CotEditor 的类型转换和文档引用错误保留在本地记录中，不抹去失败尝试。

这些仍是实验适配器，不是统一生产级 CLI：参数错误协议、版本/摘要固定策略、超时后的结果归属还需统一；未测试复杂 Office 排版、引擎渲染/导出、用户现有项目、权限拒绝、升级失效或长期并发。

## 下一阶段

在没有可用原生 CLI / 脚本接口的已授权目标上验证 REA 的具体增量，记录“分析前未知 → 分析证据 → 真实动作与读回”。当前结果证明的是多后端任务工作流可复用，不是任意应用自动 CLI 化。
